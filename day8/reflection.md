# Day 8 Reflection

## 1. Most Difficult Concept

The most difficult concept for me was understanding how a system can handle a large number of users without becoming slow or unreliable. Learning about caching, load balancing, database transactions, and horizontal scaling helped me understand that each component solves a particular problem. I overcame this challenge by breaking system design into smaller steps: identifying requirements, estimating traffic, designing API endpoints, creating a data model, and explaining the architecture. Working through the TicketHub example helped me understand why these decisions matter.

## 2. Capstone Improvement

One area I would improve in my QuickNotes capstone is the explanation and demonstration of how the API communicates with the application. I would show more clearly how requests are sent, how responses are received, and how errors are handled. I would also improve the architecture diagram by making the relationships between the application, API, and data storage easier to understand. I have not yet documented specific feedback from a reviewer, so these improvements are based on my own review of the project requirements and what I have learned.

## 3. What I Will Learn Next

Next, I plan to learn Node.js and Express so that I can build a real backend for my QuickNotes application. I also want to learn PostgreSQL to store notes persistently and practise writing SQL queries, creating relationships, and enforcing database constraints. These skills will help me move from designing systems to building and testing full-stack applications.
